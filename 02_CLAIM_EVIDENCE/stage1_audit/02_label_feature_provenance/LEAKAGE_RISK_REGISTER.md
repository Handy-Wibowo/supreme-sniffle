# Leakage risk register

## Executive findings

- **Proven label leakage (historical probes only):** Explicit probe code computes `TLDLegitimateProb` from label means before a later split. On PhiUSIIL, it groups *all* corpus labels by `TLDLength` before constructing row/domain partitions (`phishing/handoff_dataset_decision/D_probe_code/02_phiusiil_contrast.py:63-65`). On PhreshPhish probes, it groups original train-partition labels before a later random/site-disjoint split of the combined pool (`.../03_phreshphish_protocol.py:75-78`; `phishing/_p_memo.py:51-55`); rows later sampled into test can contribute. This proves leakage in those scripts, but those scripts are not E5/E6 production code.
- **Current A0/A1 stored-column provenance: high-risk unknown.** Current 47/41-feature runs consume the stored `TLDLegitimateProb` and `URLCharProb` as-is from the cleaned Parquet (`Experiment/5 - PhiUSIIL Focused Ablation/src/data.py:33-55,111-132`). No upstream feature-generation code is included. Direct local recomputation showed the stored `TLDLegitimateProb` does *not* equal cleaned-table whole-label mean `y_phish` by `TLDLength` for any of 235,370 rows; therefore the exact historical formula cannot be asserted as the stored column’s proven formula. It remains unknown whether the source value used target labels, a separate population, or some other computation.
- **High separability is verified; causal label-proxy mechanism is not.** Current clean-table direction-free AUC: `LineOfCode=0.9902829`, `NoOfExternalRef=0.9880330`, `URLCharProb=0.7676412`, `TLDLegitimateProb=0.6087605`, `CharContinuationRate=0.7434736`. These are descriptive of the full labeled dataset; neither AUC nor a high F1 is proof of label derivation.
- **Current model fitting separation: code-supported.** E5 extracts A2 deterministically from each URL and fits estimators only with selected train IDs/labels; E6 fits on PhiUSIIL train IDs only and predicts both source reference and target cohorts. That is train/test isolation for the model estimator. It does not prove that stored A0/A1 feature values were computed without future/test information upstream.
- **Feature screening scope: whole-dataset, not train-only.** E1 notebook computes label-related univariate AUC across every row before constructing/saving splits. It reports AUC, but the code’s effective drop list removes only URLSimilarityIndex and title matches (plus FILENAME), not LineOfCode or NoOfExternalRef despite table verdicts saying otherwise.
- **Causal ceiling support: FAIL.** A1–A0 ablation supports only a small conditional feature-group contrast (and paired bootstrap on same site-disjoint rows). It does not explain the source of A0’s ceiling; no design intervenes on label creation, page collection, or feature provenance, and the data hold one source corpus.

## Specific feature provenance notes

### `TLDLegitimateProb`

The name itself is not trustworthy evidence of its computation or semantic direction. Historical probe code calculates mean `y_phish` by *TLDLength*—not by TLD string identity—so the label name “legitimate probability” does not match that probe target unless inverted. The old PhiUSIIL probe uses all labels before split; old Phresh probe uses train-partition labels before a later re-split. Current A2 `FEATURE_ORDER` has no such field and current E4 asserts its absence. Current A0/A1 still inherit the precomputed column, whose exact generating script/reference population remains absent. Thus: proven leakage in old probes; unresolved high risk in current A0/A1 source provenance; not proven leakage in the current stored feature.

### `URLCharProb`

This is included in legacy A0/A1 but not A2. Local source schema confirms the value column exists, but no executable producer was found in local source. Generic documentation calls it statistical/character probability; that does not reveal whether its learned reference corpus was independent of the rows being evaluated or if labels were consumed. Current evidence supports only whole-data separability AUC ~0.768 and missing provenance; classify as unknown provenance plus leakage risk, not proven leakage.

### Content and aggregate/statistical features

`LineOfCode`, `LargestLineLength`, resource/reference counts, UI/page flags and semantic content flags are stored columns. The raw source site paper/extraction pipeline is not present locally in the executable code audited. High `LineOfCode` and `NoOfExternalRef` AUCs warrant high-separability scrutiny. No exact formula, collection timestamp, per-row source page snapshot, or train-only producer fit is shown. `CharContinuationRate`, TLD/URL probability-like fields, and AUC screen are statistical-derived candidates but their exact producer stage is unverified. Avoid claiming the six A1 ablated columns caused the A0 ceiling: two high-AUC fields are in A0 and removed by A1, but an ablation difference only supports a conditional aggregate predictive association.

## What is not established

1. That current stored `TLDLegitimateProb` was computed with the exact historical target-encoding formula. A direct full clean-table comparison rejected that formula on every row.
2. That `URLCharProb` is label-derived; neither its original training corpus nor formula is locally available.
3. That all A0/A1 source-feature values were computed exclusively from each model train fold. The current training pipeline does not refit them, and no upstream producer/fitting metadata resolves this.
4. That high AUC causes ceiling performance, that content features cause the score ceiling, or that removal of six columns identifies individual contributions.
5. That cross-corpus transfer failure is caused by time, domain identity, vendor, or any single shift mechanism.
6. That whole-dataset AUC screening contaminates current model fit values. It uses all labels for a descriptive audit before train/test split but does not change model inputs or split assignments; selection/drop implementation is fixed in notebook code.
