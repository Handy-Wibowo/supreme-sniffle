# Experiments 1–8: reproducibility audit

**Scope.** This is a local artifact/provenance audit of `Experiment/` and `phishing/AI_Review_SINTA2_Package_v8/`. No manuscript, experiment source, dataset, notebook, or existing evidence was changed. Verification runs were directed to this audit folder. No expensive model training was run. Matrix: `REPRODUCIBILITY_MATRIX.csv`; exact executed commands and observed exits: `COMMAND_LOG.md`.

## Interpretation of reproducibility levels

- **Arithmetical reproducibility:** recomputation from saved predictions/scores reproduces reported metrics, confusion counts, thresholds or derived tables; does not prove those predictions came from a retrained model.
- **Artifact replay:** saved outputs, manifests, hashes, inputs and/or models are sufficiently present to validate numerical output lineage. It does not imply full training can be reproduced from the review package alone.
- **Executable reproducibility:** checked-in code can be executed with available inputs and specified dependencies in a documented environment, without changing source evidence. Colab notebooks with mutable/unpinned install steps or absent raw inputs are conditional, not fully reproducible.
- **Full training reproducibility:** fresh model fitting on declared splits can be repeated from source, pinned data/code/environment/seeds. No full training was repeated for this audit; historical successful runs are explicitly labeled historical.

## Overall finding

**The evidence is asymmetric.** E4–E7 have substantial saved prediction/model lineage, hashes, split manifests and independent metric or prediction checks; E1/E2 hashes establish local cleaned-artifact integrity; E3 is materially weaker because its outputs are aggregate metrics without row-level predictions or model files; E8 is descriptive replay on E4 errors. The v8 review package is a review subset, not a self-contained reproducibility package: it excludes raw datasets, E4 outputs, most E6 predictions, implementation source, and E7 predictions/models. No experiment supports a *blind/prospective* evaluation claim based on this local record.

E4, E5 temporal, E6, E7 and E8 explicitly identify the PhreshPhish temporal test partition as previously inspected in earlier probes/work. E7 correctly limits threshold selection to validation scores, but that does not make the overall test period blind. Five seeds are model fits on the same time partition, not independent future periods. E6’s target is a previously inspected temporal cohort and its metrics are exploratory. E8 reuses E4 predictions. The E1 temporal split file is a collection-plan placeholder, not a prospective holdout result.

Classification: artifact integrity PASS, code execution conditional on Colab/raw CSV, fresh cleaning rerun not performed; no full training applies. The temporal manifest says collection was still in progress, so no prospective evaluation may be inferred from E1.

## E4 — PhreshPhish temporal audit

Run entry point `Experiment/4 - PhreshPhish Temporal Audit/run_temporal.py`; the author notebook is documented as protocol source, and `04_PhreshPhish_Temporal_Audit.ipynb` is an exploratory notebook history. Inputs are 56 train plus 21 test Parquet shards (77 total), represented by per-shard row/size/hash manifest. Run design fixes cutoff 2025-09-08, threshold .5, five seeds (13, 42, 2024, 777, 31415), primary seed 13, LightGBM 300/0.05/63, 1,000 domain bootstrap samples and recorded unparseable URL exclusion policy. The local run folder contains model binaries and parameters, train/test split manifests, row ledger, exclusions, per-URL predictions, results, feature schema, and input/output SHA manifests. Python and key library versions are recorded in `design.json`, but a complete lockfile is not established. Private PSL suffixes disabled; source expressly records that no PSL snapshot/checksum exists.

For this audit, SHA-256 matched all 28 files listed in E4's output manifest. The end-to-end verifier was run with the full 168,035-row test partition, all five saved models, and a 40,000-row train sample. It passed 25/25 checks: test identity/labels/dates/canonical hashes/domains/features, train-sample lineage, `domain_seen`, exact probabilities (max absolute delta 0 for all five seeds), and confusion counts. This confirms saved-model prediction replay on available inputs, not fresh fit reproducibility. Full historical run is documented as exit 0, but not rerun here. Explicit test-status field says previously inspected in exploratory probes; results are not blind/prospective. **Main gap:** no reproducible PSL identity, and historical test exposure.

Results are exploratory, not blind. A2 feature reimplementation is not equivalent to source columns and should not be conflated with exact representation parity.

## Notebook history and v8 package

`notebook_history_check.log` and `v8_notebook_history_check.log` list actual on-disk metadata only. Counts and absence of error outputs show stored execution history, not independent execution or reproducibility. E4's separate AUTHOR_RUN notebook has null code-cell execution counts; local runner logs and saved output manifests document its historical full run. v8 package documentation states explicitly that it intentionally omits large per-row predictions, raw data and E6–E8 implementation source. The package-level verification documents should be interpreted as recorded reviewer/worker claims; this audit directly reran the E6 workspace metric verifier and E7/E4 checks, but did not rerun package validators or any notebooks.

## Bottom line for manuscript language

Safe: E4 saved predictions are exactly replayed by saved models on current raw shards; E6/E7 saved metrics and E7 validation-selected thresholds are independently replayable; E8 confusion counts replay from prediction CSV; E1/E2 cleaned artifacts match declared hashes. Not supported: claim that any PhreshPhish test evaluation was blind or prospective; claim that E4 uses a uniquely identified PSL snapshot; claim that the v8 package alone can regenerate all experiment results; or claim that this audit freshly retrained any of the models. E3's aggregate-only metrics and v8's intentionally slim evidence package are the largest gaps for an external reviewer.
